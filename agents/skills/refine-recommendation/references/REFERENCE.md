# refine-recommendation reference

## Project-specific recommendation priorities
MetroPulse should remain:
1. explainable
2. demo-ready
3. academically grounded
4. easy to iterate

## Expected recommendation dimensions
- popularity (PageRank)
- connectivity (transition probability)
- preference match
- travel cost penalty

## Typical adjustment scenarios
- homepage results feel too generic
- too many popular stations dominate
- preference tags have too little impact
- long travel routes appear too often
- textual reasons do not align with actual score breakdown

## Recommendation change principle
Change one thing at a time where possible:
- weights
- normalization
- reason generation
- filtering constraints
